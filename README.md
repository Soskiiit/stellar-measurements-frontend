# Stellar Measurements Frontend (StarParallax)

Репозиторий фронтенд-приложения по дисциплине «Проектирование систем и продуктовая веб-разработка».

- **Тема:** Определение расстояния до звезды в Млечном пути по ее годовому параллаксу
- **Услуги:** Звёзды (`parallax_stars`)
- **Заявка:** Расчёт расстояния с указанием параллакса по каждой

---

## Описание страниц приложения, кнопок и полей

### 1. Навигационная панель (`NavigationBar`)
Расположена в нижней части экрана на всех страницах и состоит из **4 пунктов**:
1. **Кнопка «Лента»** — доступна для гостя. Переключает интерфейс на просмотр ленты звёзд.
2. **Кнопка «Добавить»** — заблокирована (`disabled`) для гостя, доступна авторизованному создателю. Открывает двухшаговую страницу добавления звезды.
3. **Кнопка «Каталог»** — доступна для гостя. Переключает интерфейс на плитку карточек звёзд.
4. **Кнопка «Вход» / «Выход»** — переключение между интерфейсом гостя и интерфейсом пользователя. Для гостя открывает страницу авторизации; для пользователя выполняет деавторизацию (отзыв JWT в blacklist Redis) и сбрасывает фильтр пользователя.

В шапке после авторизации отображается логин текущего пользователя.

### 2. Страница каталога звёзд (Плитка)

#### Поля:
- **Ползунок фильтрации расстояния (`Form.Range`)**: максимальное расстояние до звезды в парсеках (0–1000 пк). Значение фильтра хранится в **Redux Toolkit** (`filterSlice`) и передаётся в запрос к бэкенду `GET /api/parallax_stars?distance=...`.
- **Индикатор текущего значения фильтра** (`D пк`) и граничные метки шкалы.
- **Поля карточки звезды**: изображение (через прокси `/s3` из Silo/MinIO, с fallback-картинкой при отсутствии/ошибке), название, расстояние (`D = X.XX пк`), счётчик лайков.
- **Признак авторства `is_creator`**: на карточках собственных звёзд пользователя показывается кнопка удаления.

#### Кнопки:
- **«Поиск»** — применяет фильтр из Redux и перезапрашивает каталог с сервера.
- **Карточка звезды** — переход в ленту, начиная с выбранной звезды.
- **✕ (удаление)** — логическое удаление своей звезды (`DELETE /api/parallax_stars/{id}`, soft delete).
- **Логотип «⭗ StarParallax»** — возврат в каталог.

### 3. Страница ленты звёзд

#### Поля:
- Фоновое видео звезды (автоплей, цикл; URL через прокси `/s3`, fallback-видео при ошибке).
- Название, описание («больше ▼ / меньше ▲»), параллакс (`X.XXX"`), расстояние (`X.XX пк`), счётчик лайков.
- Признак `is_liked`: активный лайк текущего пользователя подсвечивается.

#### Кнопки:
- **♥ (лайк)** — поставить/отменить лайк (`POST /api/parallax_stars/{id}/like`, тело `{like: 1|0}`). Для гостя заблокирована.
- **«Следующая» (стрелка вниз)** — следующая звезда (`GET /api/parallax_stars/feed?id=...&next=true`).

### 4. Страница авторизации (`AuthPage`)
- Поля **Логин** и **Пароль**, кнопки **«Войти»** / **«Зарегистрироваться»** (переключение режима).
- Запросы `POST /api/users/login` и `POST /api/users/register` выполняются **вручную через axios**, состояние передаётся в Redux обычными экшенами (`authStarted/authSucceeded/authFailed`) — без кодогенерации и thunk.
- Бэкенд выставляет httpOnly-cookie `access_token`/`token` (JWT, 24 ч). Токен дублируется в `localStorage` (`access_token`) для демонстрации запросов в Insomnia/Postman.
- Состояние Redux не персистится: **по F5 интерфейс возвращается в состояние гостя, хотя JWT-кука остаётся** в браузере.
- Подсказка: тестовый аккаунт `user1 / password1`.

### 5. Страница добавления звезды (`AddStarPage`, два шага)
- **Шаг 1 «Новая звезда»**: медиа (фото/видео, загружаются в MinIO через бэкенд) и название → **«Далее»** создаёт черновик (`POST /api/parallax_stars`, multipart).
- **Шаг 2 «Публикация черновика»**: превью медиа, название (readonly), описание (до 255 символов), параллакс (0.001–9.999), расстояние (0.01–999.99) → **«Опубликовать»** (`PUT /api/parallax_stars/{id}/publish`).
- Если у пользователя уже есть активный черновик (`GET /api/parallax_stars/draft`), страница сразу открывает шаг 2.

### 6. Индикация загрузки
На время любого AJAX-запроса поверх приложения показывается блокирующий оверлей со спиннером (`LoadingOverlay`): счётчик запросов ведётся в `loadingSlice` через interceptors axios.

## Архитектура состояния (Redux Toolkit)

```
src/store/
├── index.ts              # configureStore + axios-interceptors счётчика загрузки
├── hooks.ts              # типизированные useAppDispatch / useAppSelector
├── authSlice.ts          # интерфейс гость/пользователь (ручные экшены, без thunk)
├── filterSlice.ts        # фильтр услуг по расстоянию (сброс при выходе)
├── loadingSlice.ts       # счётчик выполняющихся запросов
└── parallaxStarsSlice.ts # thunk'и домена услуг через сгенерированный API:
                          # fetchParallaxStarsCatalog, fetchParallaxStarFeed,
                          # fetchParallaxStarDraft, createParallaxStarDraft,
                          # publishParallaxStar, deleteParallaxStar,
                          # toggleParallaxStarLike
```

- Middleware: `redux-thunk` (входит в `configureStore`), redux-devtools-extension совместимо.
- **Кодогенерация**: `npm run generate:api` — `openapi-generator-cli` (генератор `typescript-axios`) из `api/swagger.json` (копия `docs/swagger.json` бэкенда) → `src/api/generated/`. Thunk'и используют сгенерированный `ParallaxStarsApi` поверх общего axios-инстанса.
- **Mock-fallback**: при недоступном бэкенде (сетевая ошибка/5xx) гостю возвращаются mock-объекты из `src/data/mockParallaxStars.ts` в формате сериализаторов API (`src/data/mockApi.ts`); в интерфейсе показывается примечание. Для авторизованного пользователя ошибки показываются без fallback.

## Проксирование (CORS)

`vite.config.ts`, два маршрута обратного прокси:
- `/api` → `http://localhost:8080` — REST API веб-сервиса;
- `/s3` → `http://localhost:9002` — объекты Silo (MinIO); префикс `/s3` срезается rewrite. Прямые URL MinIO из ответов API (`http://localhost:9002/...`) переписываются в `/s3/...` хелпером `toS3ProxyUrl` (`src/api/media.ts`).

## Запуск проекта

### Фронтенд
```bash
npm install
npm run dev        # http://localhost:3000
```

### Бэкенд (для режимов с реальными данными)
Из репозитория `stellar-measurements-backend` (ветка `jwt-authentication`):
```bash
docker compose up -d postgres minio redis
go run ./cmd/migrate          # миграции + seed (звёзды, пользователи, лайки)
REDIS_PASSWORD=password go run ./cmd/parallax_stars   # :8080
```
Без бэкенда фронтенд работает в гостевом режиме на mock-данных.

### Кодогенерация API
```bash
npm run generate:api
```

### E2E-проверка (headless Chromium, 30 проверок + скриншоты)
При запущенных фронтенде и бэкенде:
```bash
node scripts/verify-lab6.mjs
```
Скриншоты сценариев сохраняются в `resources/screenshots/`.
